## Style for comments and documentation

- Write in simple, plain language, as if explaining to a colleague.
- One idea per sentence. Maximum 20 words per sentence.
- Use the active voice: "The function returns the list" rather than "The list is returned by the function."
- Avoid jargon and Anglicisms when a common term exists. If a technical term is necessary, explain it once.
- A comment should explain the WHY, not the WHAT. Do not restate what the code already expresses.
- Do not add comments if the code is self-explanatory.
- In text files (README, docs): use short sentences, bullet points for steps, and one concrete example for each concept.
- Do not use undefined abbreviations.

## README and documentation

- Write the README and documentation in English.
- Keep `README.md` concise (maximum 40 lines): project overview, basic installation, quick start, and links to further information.
- Place detailed instructions, examples, and technical references in `DOCUMENTATION.md`. Create this file if it does not already exist, and include a link to it in the README.
- Use short sentences (maximum 20 words), with one idea per sentence.
- Provide one concrete example for each concept explained.
